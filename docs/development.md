# Development

## Prerequisites

```bash
sudo apt install -y libfcitx5core-dev libfcitx5config-dev libfcitx5utils-dev \
  extra-cmake-modules build-essential cmake
```

## Build

All commands run from `fcitx5-plugin/`:

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
cmake --install build   # installs to ~/.local
```

## Tests

```bash
cmake -B build -DBUILD_TESTING=ON
cmake --build build --target test_engine   # build tests only
cd build && ctest --output-on-failure       # run tests
```

Run a single test case:
```bash
./build/tests/test_engine "Literal mode: Enter commits"
```

## Code Style

Formatting is enforced by clang-format (Google style, 120 columns). The CI runs
`clang-format --dry-run --Werror` on every PR and fails on unformatted code.

```bash
# Check formatting
clang-format --dry-run --Werror $(git ls-files '*.cpp' '*.h')

# Fix formatting
clang-format -i $(git ls-files '*.cpp' '*.h')
```

### Naming

Follows [Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html)
naming rules:

| Element | Rule | Example |
|---|---|---|
| Files | lowercase + underscores | `engine_logic.cpp` |
| Types (class/struct/enum) | CapWords | `EngineLogic`, `Modifiers` |
| Functions / methods | camelCase | `processKey`, `pageSize()` |
| Variables (locals, params) | snake_case | `page_offset`, `text` |
| Class data members | snake_case + trailing `_` | `dict_`, `pageSize_` |
| Struct data members | plain snake_case | `slashBuffer` |
| Constants & enumerators | `k` + CapWords | `kMaxCodeLen`, `kNone` |
| Namespaces | lowercase | `keys` |
| `keys::` keysym constants | CapWords (X11 parity) | `keys::Control_L` |

Two deliberate deviations — do not "fix" these:
- Functions/methods are **camelCase**, not Google's CapWords
- `keys::` constants stay CapWords to mirror X11 keysym names (`XK_Control_L`)

See [CLAUDE.md](../CLAUDE.md) for the full conventions reference.

## Architecture

```
Fcitx5 adapter          freewubi.cpp, fcitx_output.h
    ↓
Engine logic            engine_logic.cpp, engine_types.h   (no fcitx5 deps)
    ↓
Dictionaries             wubi_dict.cpp, pinyin_dict.cpp      (no fcitx5 deps)
```

**Key event flow:** Fcitx5 key event → `FreeWubiEngine::keyEvent()` (freewubi.cpp)
→ `EngineLogic::processKey()` (engine_logic.cpp) → dictionary lookup → candidate list
→ `IEngineOutput` interface → FcitxOutput or TestOutput.

### Three-layer design

- **Fcitx5 adapter** — translates Fcitx5 key events to portable `KeyInput`, renders
  candidates and preedit via Fcitx5 APIs
- **Engine logic** — pure C++ state machine with no Fcitx5 dependency, fully testable
  via `IEngineOutput` interface
- **Dictionaries** — loads YAML/TSV data files, provides lookup by code

### Two-tier dictionary

- `dict_`: Full Wubi 86 dictionary (~89k entries)
- `dict_common_`: Common characters only (generated by `scripts/build_common_dict.py`)

`EngineLogic::activeDict()` returns `dict_common_` by default, `dict_` when rare mode
is on.

## CI Workflows

| Workflow | Trigger | What it does |
|---|---|---|
| `format-check.yml` | Push to `main`, PRs | `clang-format --dry-run --Werror` on all `.cpp`/`.h` |
| `test.yml` | Push to `main`, PRs | Build with `-DBUILD_TESTING=ON`, run `ctest` |
| `release.yml` | Push tag `v*` | Build Release, package tarball, create GitHub Release |

## Contributing

1. Fork the repo and create a branch
2. Make your changes, format with `clang-format -i`
3. Push and open a pull request
4. CI must pass (`clang-format` ✅ + `cpp-tests` ✅) before merging
